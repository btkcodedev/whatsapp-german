# CLAUDE.md — WhatsApp German Word Channel

## Project Overview

Posts one AI-generated German vocabulary word (CEFR-leveled, default A1) to a WhatsApp Channel every morning. Fully automated, no server, free to run.

**Stack**: TypeScript, Node.js, [Baileys](https://github.com/WhiskeySockets/Baileys) (WhatsApp multi-device protocol, no headless browser), Google Gemini, MongoDB Atlas, GitHub Actions.

There is deliberately no DM bot / interactive component. It was removed — it required an always-on server to hold the WhatsApp connection open for replies, which conflicts with the "free, no server" design. Don't re-add it without changing that constraint first.

---

## Architecture

```
GitHub Actions (cron, daily, ubuntu-latest runner — ephemeral, no persistent disk)
  1. checkout
  2. npm start -> src/index.ts
       - load Baileys session from MongoDB (src/waAuth.ts)
       - ask Gemini for today's word (level-aware, avoids past words)
       - post to the WhatsApp Channel
       - save updated progress back to MongoDB
  3. runner destroyed, nothing persists locally

MongoDB Atlas (free M0)
  - WaAuth collection: Baileys session creds (a few KB, not a browser profile)
  - ChannelProgress collection: current day counter + words already used
```

## Key Files

| File | Purpose |
|------|---------|
| `src/index.ts` | Daily job — generate word, connect, post, save progress. Entry point for `npm start`. |
| `src/link.ts` | One-time **local** QR link (`npm run link`). Never run in CI — QR scanning needs a human with a phone. |
| `src/waAuth.ts` | MongoDB-backed Baileys `AuthenticationState` — mirrors Baileys' official `useMultiFileAuthState`, swaps fs for Mongo. |
| `src/db.ts` | Mongo connection, `ChannelProgress` schema/helpers, `WaAuth` schema. |
| `src/vocabulary.ts` | CEFR topic lists, Gemini prompt + model-fallback chain, message formatting. |
| `.github/workflows/daily-word.yml` | The cron. `30 2 * * *` = 8:00 AM IST. |

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `GEMINI_API_KEY` | ✅ | Google Gemini API key (free tier) |
| `MONGODB_URI` | ✅ | Same URI used for `npm run link` locally and the GitHub Actions secret — must match or the deployed job won't see the linked session |
| `CHANNEL_ID` | ✅ | WhatsApp Channel invite code (the part after `https://whatsapp.com/channel/`) |
| `CHANNEL_LEVEL` | ❌ | CEFR level for the channel, default `A1` |

## Gemini Model Fallback

`src/vocabulary.ts`'s `generateJSON()` tries a chain of model IDs (`MODEL_FALLBACKS`), newest first, falling through on 404/429/503/quota errors. This exists because Google renames/retires Flash model IDs periodically without much notice (`gemini-1.5-flash` 404'd on us once already). If every entry in the chain is dead, bump it — check https://ai.google.dev/gemini-api/docs/pricing for current free-tier model IDs.

## Common Tasks

**Change the model fallback chain**: edit `MODEL_FALLBACKS` in `src/vocabulary.ts`.

**Add/edit CEFR topics**: edit `TOPICS` in `src/vocabulary.ts`.

**Change the message format**: edit `formatWordMessage()` in `src/vocabulary.ts`. Keep it emoji-free / plain-dictionary style (explicit design choice, not an oversight) and don't reference DM bot commands — there is no DM bot.

**Reset the day counter**: connect to Mongo and overwrite the `ChannelProgress` doc (`_id: 'channel'`) — `currentDay: 1`, `wordsUsed: []` if you also want to clear the no-repeat memory.

**Re-link WhatsApp** (session expired/logged out): `npm run link` locally, using the *same* `MONGODB_URI` as the GitHub Actions secret.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `MONGODB_URI is not set` | Missing from `.env` (local) or the GitHub Actions secret |
| `Could not connect to any servers in your MongoDB Atlas cluster` | Atlas Network Access doesn't have `0.0.0.0/0` allowed — GitHub Actions runners have no fixed IP |
| `No linked WhatsApp session found in MongoDB` | Run `npm run link` locally first |
| `models/... is not found for API version v1beta` | Every entry in `MODEL_FALLBACKS` is now dead — check current model IDs and update the list |
| A "fresh" Actions run still fails with an error you already fixed | You likely clicked **Re-run jobs** on an old run (reuses that run's original commit SHA) instead of **Run workflow** on the workflow itself (uses latest `main`) |

## Security Notes

- Never commit `.env` — the workflow reads secrets only from GitHub Actions
- Baileys session lives only in MongoDB + the `MONGODB_URI` secret, never in the repo
- Use a dedicated WhatsApp number, not a personal one — automation risks a ban
- This repo's git history was rewritten once (`git filter-repo`) to strip a leaked `whatsapp-web.js` session that had been committed pre-migration. If you're reading old commit SHAs from before that rewrite anywhere external (issues, forks, local clones), they no longer match `origin/main`.
